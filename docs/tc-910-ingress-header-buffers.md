# TC-910: dstack ingress request headers

The tee.node production ingress has nginx's default `large_client_header_buffers 4 8k`. Session activation (`POST /delegate`) places the signed delegation in one `Authorization` header; replication login headers can exceed 8 KiB and fail with `400 Request Header Or Cookie Too Large`.

`deploy/ingress/Dockerfile` wraps the pinned `dstacktee/dstack-ingress:1.4` image and copies `header-buffers.conf` to `/etc/nginx/conf.d/00-header-buffers.conf`. 1.20.1 shipped the wrapper on `dstack-ingress:20250924`; #261 moved it to `1.4`, which also honours `CLIENT_MAX_BODY_SIZE`. The compose sets it to 32 MB and leaves the proxy timeouts at nginx's defaults (TC-940). The directive `large_client_header_buffers 4 32k;` resides in the nginx `http {}` context. The prefixed filename is loaded before its generated `default.conf` server block. This raises the per-header-line capacity while retaining four buffers.

The upstream entrypoint's `setup_nginx_conf` generates `default.conf`; it does not remove the custom `00-header-buffers.conf` drop-in. The directive is valid in `http` context.

## Logging (TC-970)

The wrapper replaces the base image's request logging. Upstream `nginx.conf` sets `access_log /var/log/nginx/access.log main`. The `main` format includes the client address, the raw request line (which carries `/signed/kv/<ticket>`, `/hooks/events?ticket=…` and `/public/<space_id>/…`), `Referer`, `User-Agent` and `X-Forwarded-For`. That file, like `error.log`, is a regular file that nothing rotates: the image has no logrotate binary or cron.

`redacted-logging.conf` (copied to `conf.d/00-redacted-logging.conf`) logs one JSON line per request to stdout:
- method, if it is GET, HEAD, POST, PUT, PATCH, DELETE or OPTIONS, else `<other>`;
- route class, mapped from `$uri` by an allowlist that mirrors the node's mounted route shapes, with `<other>` for anything else. It classifies the path; it is not the route Rocket matched. The method is ignored, so an `OPTIONS` preflight logs under the path's class, and nginx compares literal keys case-insensitively;
- protocol, status, bytes;
- request time, upstream status and upstream timings.

It never logs the query string, client address or headers. In the http context, `error_log` is `/dev/stderr emerg`, because request-context errors embed the client address and request line at every level, `alert` included. The Dockerfile removes the base `access_log` line, points the main `error_log` and the compiled-in `/var/log/nginx/error.log` at stderr, and fails the build if the base `nginx.conf` changes shape. When the node adds a route, add it to the map, or its requests are logged as `<other>`.

Size: the access log goes to the container's stdout. Whether that is rotated depends on the docker daemon's logging driver on the CVM; the compose sets no `logging:` options, as for the node container.

`deploy/ingress/test-redacted-logging.sh` builds the wrapper and runs it with the server block generated by the entrypoint's own `setup_nginx_conf`, using a self-signed certificate. It sends credential-bearing requests from a second container and asserts:
- none of the markers or the client address appear in stdout, stderr or `/var/log/nginx`;
- each request is logged as a valid JSON line with the expected method, route class and status, over HTTP/2 and HTTP/1.1, including a 400 raised before routing;
- a 30 KB header and a 150 MB body are accepted, and a body over 200 MiB is refused with 413.

CI runs it in the `build-ingress` job before the image is pushed. Locally: `DOCKER="sudo docker" deploy/ingress/test-redacted-logging.sh`, or `IMAGE=<ref>` to test a published wrapper.

## Deploy and rollback

1. **Build:** dispatch `docker.yml` on the release ref, then record the ingress image digest from the job summary.
2. **Check the pull:** confirm the digest pulls anonymously. A new GHCR package may start private; make it public if it is.
3. **Pin and deploy:** set the literal digest in the `dstack-ingress` compose `image:` and deploy it together with the node release that carries the compose change.
4. **Verify:** send an `Authorization` header of about 12 KB to `https://tee.node.tinycloud.xyz/delegate`; confirm the request is not a 400 and the connection is not reset.
5. **Rollback:** revert the compose `image:` line to the previous wrapper digest and redeploy. Before TC-970 (redacted logging) that is `ghcr.io/tinycloudlabs/tinycloud-node-ingress@sha256:08cf3ee4ab4054cc2657da12304ae344d6b2156c1fa11ffd7da5e64cd1bca416`: the #261 wrapper on `1.4`, with 200 MB bodies, but it writes raw request lines and client addresses to an unrotated `/var/log/nginx/access.log`. The 1.20.1 wrapper on `20250924` is `ghcr.io/tinycloudlabs/tinycloud-node-ingress@sha256:726c6d35858e50c5524cc97e789c2c8f09620e77d708bb71bdc9370e3d80ed3e`, with 32 KB headers and the default body limit. To drop the wrapper entirely, use `dstacktee/dstack-ingress:20250924@sha256:40429d78060ef3066b5f93676bf3ba7c2e9ac47d4648440febfdda558aed4b32`. The `CLIENT_MAX_BODY_SIZE` and `PROXY_*_TIMEOUT` compose lines have no effect on `20250924`.
